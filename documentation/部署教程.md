# 部署教程

## 一、环境要求

- **Node.js** 20 LTS 及以上
- **npm** 10 及以上
- 一个可正常访问的 **XBoard / v2board 后端 API**（生产环境建议与前端同域或配置好 CORS）
- 生产部署：Nginx（推荐）或任意静态托管平台

## 二、本地开发

```bash
# 1. 获取代码
git clone https://github.com/aklibk86-dev/stellar.git
cd stellar

# 2. 安装依赖（锁定版本，建议使用 npm ci）
npm ci

# 3. 配置开发 API
#    首次部署先复制模板：cp public/env.js.example public/env.js
#    （env.js 含真实后端地址等运营信息，已被 git 忽略不再进版本库；
#      npm run build 的 prebuild 钩子会在缺失时自动从模板复制）
#    然后编辑 public/env.js，填写 api 下的后端地址与后端类型
#    （该项目唯一的运行时配置入口，修改后无需重新构建）

# 4. 启动开发服务器
npm run dev
```

- 开发服务器默认端口为 Vite 默认的 **5173**（访问 `http://localhost:5173`）；如需固定为 3100，可取消 `vite.config.ts` 中 `server` 配置块的注释。
- 开发模式支持热更新（HMR）。

## 三、生产构建

```bash
npm run build
```

- `prebuild` 钩子会先执行 `node scripts/ensure-env.js`：当 `public/env.js` 缺失时自动从 `public/env.js.example` 复制生成（全新 clone 无需手工复制即可构建成功，但产出的是模板占位配置，**部署前必须检查并替换真实后端地址/客服 ID 等**）。
- 命令随后执行 `vue-tsc -b` 类型检查，再执行 `vite build`。
- 产物输出到 `dist/` 目录：
  - `dist/index.html` —— 入口页（含安全响应头、加载动画、默认配置兜底）
  - `dist/env.js` —— 运行时配置（由 `public/env.js` 复制）
  - `dist/assets/` —— 哈希命名的 JS/CSS 与静态资源
  - `dist/client-logos/` —— 客户端 Logo
- 本地预览构建产物：

```bash
npm run preview
```

> 注意：`vite.config.ts` 中 `base: './'` 使产物可部署到任意子路径，`public/env.js` 的 `window.routerBase` 控制前端路由的基准路径，两者配合即可实现子目录部署。

## 四、部署方式 A：Nginx 根目录部署（推荐）

1. 首次部署先复制模板并填写真实配置：`cp public/env.js.example public/env.js`（若 `env.js` 不存在，`npm run build` 会自动从模板复制，但值仍为占位，务必替换）。
2. 执行 `npm run build`，将 `dist/` 内**所有文件**上传到服务器目录（如 `/var/www/stellar`）。
3. 修改 `dist/env.js`：确保 `window.routerBase = '/'`，并按需填写 API 地址。
3. 配置 Nginx：

```nginx
server {
    listen 80;
    server_name your-domain.com;
    root /var/www/stellar;
    index index.html;

    # 同域 API 转发（可选）：前端与后端同域时使用，避免 CORS 问题
    location /api/ {
        proxy_pass http://127.0.0.1:8080/api/;
        proxy_set_header Host $host;
    }

    # env.js 禁止缓存：修改配置后无需清缓存即可生效
    location = /env.js { expires -1; add_header Cache-Control "no-store, no-cache"; }

    # SPA 路由回退（关键）：刷新 /dashboard 等路径不 404
    location / { try_files $uri $uri/ /index.html; }

    # 禁止被 iframe 嵌入（frame-ancestors 只能通过响应头生效）
    add_header Content-Security-Policy "frame-ancestors 'none'" always;
}
```

4. 重载 Nginx：`nginx -s reload`。

> 提示：`/api/` 转发不是必须的。前端支持 `url_mode: 'static'` 直连任意后端地址，只需后端允许跨域（CORS）；同域转发只是更安全的推荐做法。

## 五、部署方式 B：Nginx 子目录部署

以 `https://example.com/stellar/` 为例：

1. 构建产物上传到 `/var/www/stellar/`。
2. 修改 `dist/env.js`：

```js
window.routerBase = '/stellar/'
```

3. 配置 Nginx：

```nginx
location /stellar/ {
    alias /var/www/stellar/;
    try_files $uri $uri/ /stellar/index.html;
}
```

4. 若使用同域 API 转发，把转发路径放在 `routerBase` 之外（如 `/api/` 不受 `stellar/` 前缀影响）。

## 六、部署方式 C：静态托管平台（Vercel / Cloudflare Pages / Railway）

项目内置 `scripts/generate-env.js`，可在**构建时**用 `STELLAR_` 前缀的环境变量覆盖 `env.js` 中的配置，无需手工改文件，适合 CI/CD 流程。

**Vercel 示例：**

- Build Command：`node scripts/ensure-env.js && node scripts/generate-env.js && npm run build`
- （`ensure-env.js` 保证全新 clone 下 `env.js` 存在，`generate-env.js` 再用 `STELLAR_` 环境变量覆盖其值；`npm run build` 内置的 prebuild 也会执行 ensure-env，重复执行无副作用。）
- Output Directory：`dist`
- 在项目设置中添加环境变量（见下表）

## 七、部署方式 D：任意静态服务器

`dist/` 是纯静态产物，直接拷贝到任意 Web 服务器即可，但必须满足两点：

1. **SPA 路由回退**：所有未知路径回退到 `index.html`（否则刷新子页面 404）。
2. **`env.js` 不缓存**：配置修改才能即时生效。

## 八、缓存策略（推荐）

| 文件 | 策略 |
| --- | --- |
| `index.html` | 不缓存或短缓存（如 `no-cache`） |
| `env.js` | `no-store, no-cache`（修改配置即时生效） |
| `assets/*.[hash].js/css` | 长期缓存 + `immutable` |
| `client-logos/*` | 可长期缓存 |

## 十、常见问题

**Q：页面能打开，但所有接口报跨域（CORS）错误？**
- 使用 `url_mode: 'static'` 直连后端时，后端需允许前端来源跨域；更稳妥的做法是 Nginx 同域转发 `/api/`。

**Q：刷新 /dashboard 等路径出现 404？**
- 未配置 SPA 回退。Nginx 需添加 `try_files $uri $uri/ /index.html;`（子目录部署对应 `/stellar/index.html`）。

**Q：修改 env.js 后配置不生效？**
- 浏览器或 CDN 缓存了该文件。检查 Nginx 缓存配置（`location = /env.js { expires -1; ... }`），并强制刷新。

**Q：多 API 健康检测页反复出现？**
- 确认 `static_base_urls` 中至少一个地址可访问 `check_path` 对应接口；不需要检测时把 `api.check_enabled` 设为 `false`。

**Q：子目录部署后资源 404？**
- 检查 `window.routerBase` 是否为首尾完整斜杠（如 `/stellar/`）；同时确认 Nginx `alias` 与 `try_files` 路径一致。

**Q：`auto` 后端探测不准？**
- `auto` 模式根据 `guest/comm/config` 返回字段特征判断，无法判断时默认按 Xboard 处理。若后端特殊，建议直接在 `env.js` 中显式指定 `backend_type: 'xboard' | 'v2board'`。

## 十一、安全建议

- 生产环境强制 HTTPS，并在响应头设置 `Content-Security-Policy: frame-ancestors 'none'` 禁止被 iframe 嵌入（`frame-ancestors` **只能通过 HTTP 响应头生效**，写在 index.html 的 `<meta>` 中会被浏览器忽略并提示告警）。
- 不在 `env.js` 中存放密码、Token、订阅链接等私密信息。
- 后端 CORS 限制来源，优先使用同域转发。
- 客服安全模式（Tawk Secure Mode）的 HMAC 必须由服务端生成，禁止把通用 hash 或 API Key 写入前端文件。
- 定期执行 `npm audit` 检查依赖安全。
