### T-01 解除生产配置被 git 跟踪（仓库/配置安全）

- **现状**：`.gitignore` 第 18-19 行已写入 `# Runtime config with sensitive URLs` 与 `public/env.js`，但 `git ls-files` 显示 `public/env.js` **仍被跟踪**（早期被强制加入），其中含生产后端地址 `https://xboard.wf1.one` 与 Tawk Property ID `6a7fee6896f34e1d453f1cf8`。任何 clone/fork 都会带出运营信息。

  4. 更新 `README.md` 与 `documentation/部署教程.md` 中的配置步骤，说明"首次部署需复制 env.js.example 为 env.js"。
- **验收标准**：

### T-03 会话超时参数可配置，"记住我"语义修正（账号体验）

- **现状**：`src/stores/user.ts`：
  - L17-18：`SESSION_IDLE_LIMIT = 12 * 60 * 60 * 1000`、`SESSION_MAX_LIMIT = 24 * 60 * 60 * 1000`（硬编码）。
  - L86-102 `ensureSessionValid`：无条件按上述常量判超时并 `logout()`。
  - L69-83 `setAuthData`：`remember` 仅决定 token 存 localStorage 还是 sessionStorage，与超时策略无关。
- **影响**：勾选"记住我"的用户仍每天被强制登出；VPN 订阅用户可能一周才打开一次面板，产生"为什么又要登录"客诉。
- **修复目标**：超时时长由 `env.js` 配置，支持"不自动登出"；"记住我"与不记住采用可区分的策略。
- **建议方案**：
  1. `settings.ts` 默认值新增 `session: { idle_hours: 12, max_hours: 24 }`（0 = 不限制）；`env.d.ts` 同步类型；`public/env.js.example` 加注释示例。
  2. `user.ts` 读取配置（带默认值回退），`ensureSessionValid` 用配置值计算；`idle_hours === 0` 与 `max_hours === 0` 时跳过对应校验。
  3. "记住我"语义：`remember=true` 时若配置存在 `session.remembered_max_hours` 则使用之（默认与 max_hours 相同），保持默认行为不突变；登录页如有相关文案同步走 i18n。
  4. 更新 `documentation/配置文件详解.md` 与 README 说明。
- **验收标准**：
  - [ ] 未配置时行为与修复前完全一致（12h/24h）
  - [ ] `env.js` 配置 `max_hours: 0` 后，超过 24h 不被登出
  - [ ] 配置仅存在于 `settings.ts`/`env.d.ts`/`env.js.example`/文档，无第三处硬编码
  - [ ] `npm run build` 通过

### T-06 续费/重置流量不得静默取消他人订单（交易安全）

- **现状**：`src/views/Dashboard.vue`：
  - `handleRenew` L715-721：先 `getOrderList()` 取全部订单，把 `status === 0`（待支付）的订单**全部**逐个 `orderCancel`，再建续费单。
